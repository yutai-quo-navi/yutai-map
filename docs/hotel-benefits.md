# ホテル優待の導入状況

## 共通の画面・データ

「レア優待店 特集」の直下に「宿泊・ホテル優待 特集」を配置する。
同じセクションの下地・４列の小さな枠を使い、初期値は全国の全施設。
各枠の検索範囲は全国／100km／500km／1000km。現在地・指定地点からの直線距離で並べる。

`data/features/index.json` の `section: "hotel"` でホテル特集に振り分ける。
券の種類ごとに別の feature ID と `deadlineBenefitPattern` を設定する。
ホテルの名称・住所・座標・利用条件・確認日・公式URLを確認してから公開する。
通常の飲食店データには混ぜず、D1 の `feature_snapshots` に登録する。
未確認の施設を公開する仮データは入れない。

## 共立メンテナンス

2026-10-07確認：割引券147施設、リゾート優待券43施設。両券の2026年７月発送分の期限は2027-07-31。

- `kyoritsu-hotel-discount`：株主様ご優待割引電子チケット。国内ドーミーイン・御宿 野乃・共立リゾートと確認済みの提携ホテル。
- `kyoritsu-resort-plan`：株主様リゾートホテルご優待電子チケット。確認済みの共立リゾート。専用予約が必要。
- ランチ券は別の枠・別の期限として扱う。終了したランチ特集は飲食特集の最後に維持する。
- 公式一覧・利用条件・ホテル位置を毎月１日15:20（日本時間）に再確認する。GitHub Actions の実行時刻は遅れることがある。
- 公式情報の構造変更、未確認の新しい提携先、位置の取得失敗、施設数の20%以上の減少があれば更新を止めて前回のデータを保持する。
- 座標は公式地図を優先。公式地図の中心座標は目安と表示する。OpenPOIによる補完は名称・住所を照合した情報と出典・ライセンスを保存し、名称・住所が変わった場合は再確認する。
- 券の有効期限は `data/expiry_master.csv` と管理用Google Sheetsで管理する。ホテルの月次取得処理が券の期限を自動で推定・上書きすることはない。

## ウィンドウの並べ替え

「優待を選ぶ」「レア優待店 特集」「宿泊・ホテル優待 特集」の３枠を右上の取っ手から上下にドラッグして並べ替える。スマートフォンは取っ手だけでドラッグし、枠の本文では通常どおりスクロールする。上下キーでも移動でき、Escape・操作の中断では移動を取り消す。並び順は端末のブラウザ内に保存し、サーバーへの保存・端末間同期は行わない。ホテルタブの色分けは後続作業。
