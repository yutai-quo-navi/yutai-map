# スマホで優待期限を登録する画面の設計

本人一人用。スマホのブラウザで使い、既存の `yutai-expiry` の「期限DB」を編集する。別の期限DBは作らない。Google Apps Scriptの本人限定Webアプリを利用し、Googleアカウントの認証を使う。公開店舗検索ページへの管理リンクは追加しない。

## 入力方法

### 通常登録

会社・ブランドを検索 → 候補から選択 → 優待名・期限を入力 → シートに登録。

- 銘柄コード・正式社名は会社マスターから補完する。手で内部コードを入力する欄は設けない。
- 既存会社の優待名・カテゴリ・利用可能ブランド・期限種別を候補に使う。
- 店舗検索会社IDは既存の会社対応表から補完する。未対応会社も期限データを追加できる。
- 新規の会社はJPXの銘柄マスターから選べる。ブランドしか不明で対応がない場合は正式な会社を選ぶ。誤った企業・コードを生成しない。
- 新規会社の分類は日本語の選択肢。シートに保存するときにカテゴリコードへ変換する。
- 年・月は必須。日が分からなければ空欄。過去の期限を次の券へ自動コピーしない。
- 管理ID・確認日・ユーザー確認経路は自動で補完する。

### 画像をまとめて登録

写真ライブラリ・ファイルから最大10枚を選択 → 一括読取 → 結果を一覧で確認 → まとめて登録。

- 端末上で画像を縮小・JPEG変換し、一枚ずつ順に処理する。10枚同時の重い処理は行わないが、利用者は一度選ぶだけでよい。
- Google Driveの画像OCRを利用する。一時Google Docsを作成して文字を取得し、処理後に削除する。元画像を期限DBへ保存しない。
- 社名・ブランド・明記された証券コードから会社候補を求める。
- 期限に関連する表記の近くにある日付を候補にする。複数日付・年なし・文字の誤読は候補の選択／手入力が必要。
- OCRだけで確認済みとして保存しない。「まとめて登録」がユーザー確認となる。必要な項目は事前に一括検証する。
- 読取中は画面を開いておく。iOSのバックグラウンド移行・回線断後の自動継続は初版の対象外。保存済み件数と未登録件数を分けて表示する。
- 自動反映が失敗してもシート保存結果は保持する。保存成功の応答が不明な場合も、再追加時の重複確認で同一記録の二重保存を防ぐ。

## 重複・修正

- 重複の単位は「銘柄コード・優待名・発行回・期限種別・期限日（不明なら年月）」。
- 同じ銘柄の翌年分や別の券は追加できる。完全な重複は止め、登録済み記録を修正するボタンを出す。
- 今回の複数画像の間でも重複確認する。重複がある場合、保存前に利用者へ一覧で知らせる。
- 修正画面は社名・優待名で検索し、登録済みカードを選ぶ。既存のID・出典・ブランドなどを保持する。
- 年度を変えたときは前年行を残し、新しい行として保存する。
- PCで先に編集された記録は、版の照合で上書きを拒否する。これは本人のPC・スマホ間でも必要。

## シート → GitHub → サイト

1. スマホの保存処理はシートへ書き込み、同期を予約する。
2. PCの直接編集はインストール型onEditで同じ同期を予約する。コード経由の編集ではonEditが動かないため、スマホの保存処理から明示的に予約する。
3. 連続編集をまとめ、おおむね1分後に現在のシートを読み取る。
4. 固定リポジトリの `data/expiry_master.csv` を取得し、ID単位で更新する。シートに存在しない過去行は削除せず確認待ちの履歴として保持する。
5. GitHubの既存生成ワークフローが検証し、公開JSON・GitHub Pagesを更新する。

シート保存とサイト公開は別の完了状態。画面には「シート保存済み」「反映待ち／エラー」「GitHubへの最終送信」を表示する。GitHub送信成功をサイト公開完了とは表示しない。

## 公開前の設定

現時点はソース実装・設計プレビュー。実際のGoogle環境でのOCR・保存・自動反映は未検証。

1. 対象シートのApps Scriptへ `Code.gs`・`CompanyCatalog.gs`・`Mobile.gs`・`SheetSync.gs` と `Editor.html`・`MobileEditor.html` を配置し、マニフェストを更新する。
2. 本人限定（自分のみ）、アクセスしているユーザーとして実行するWebアプリとしてデプロイする。`/exec` URLをスマホでブックマークする。
3. Apps Scriptの初回認証。シート読み書き、作成した一時Driveファイル、外部通信、編集／時間トリガーを使う。APIキーは不要だが、Drive APIの有効化と認証はGoogle環境で確認する。
4. GitHubの対象リポジトリだけへのContents読み書き権限を持つfine-grainedトークンを、Script Propertiesの `EXPIRY_GITHUB_TOKEN` に設定する。秘密値はHTML・GitHubソース・シートに入れない。
5. 対象シートに紐づくApps Scriptで `installExpirySync` を一度実行する。接続先シートIDはScript Propertiesの `EXPIRY_SPREADSHEET_ID` に保存される。IDを公開ソースに記載しない。シートの共有・公開設定を変更する必要はない。
6. 自分のスマホで実画像1枚→10枚、追加、既存修正、重複、PC編集、GitHub Actionsの成功とサイト反映を確認する。

Apps Scriptの公開・認証・トークン設定を行える接続は、この作業の通常ツールにはない。設定が済むまで実運用可能とは扱わない。

## 銘柄マスター

出典：[JPX 東証上場銘柄一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)。2026年9月末の内国株式・REIT、3765銘柄を `CompanyCatalog.gs` に収録。既存シートの会社名・履歴と店舗検索の対応表で補完する。東証以外・直近新規上場・改称・旧券の社名はマスターの追加／更新が必要な場合がある。
