# Googleスプレッドシートで期限データを編集

既存70件を移行できるシートと、追加・訂正・X原稿を扱う編集画面を用意しました。店舗検索のトップ画面とGitHubの期限データは変更していません。

- [接続前の編集画面プレビュー](https://yutai-quo-navi.github.io/yutai-map/expiry-editor-preview.html)：検索・X原稿は確認可能。保存不可。
- 実際の編集画面はGoogleスプレッドシート内で開きます。公開Webアプリへのデプロイは不要です。

## 1. Googleの接続

ChatGPTのGoogle Drive連携を追加し、期限DBを置きたいGoogleアカウントで接続してください。操作権限の許可と、Googleアカウントへの接続は別です。接続が利用できれば、ChatGPTから既存データ入りのスプレッドシートをインポートできます。

接続後に作成するシートは「期限DB」と「使い方」の2シートです。既存の管理ID・履歴・確認状態・店舗検索用情報を保持します。期限年と期限月を別列にし、期限日の分からないデータは空欄のまま移します。

## 2. シートに編集画面を追加（初回のみ）

作成したGoogleスプレッドシートで「拡張機能 → Apps Script」を開きます。

1. `Code.gs`を[このコード](../tools/google-sheets/Code.gs)で置き換えます。
2. 左の「＋ → HTML」で`Editor`というファイルを追加し、[Editor.html](../tools/google-sheets/Editor.html)の内容を貼り付けます。
3. プロジェクト設定で「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にし、[appsscript.json](../tools/google-sheets/appsscript.json)の内容を貼り付けます。
4. 保存し、スプレッドシートを再読み込みします。「優待期限 → 編集画面を開く」を選び、初回のGoogle認証を行います。

求める権限は、このスプレッドシートの読み書きと編集画面の表示です。Gmail・他のDriveファイルへのアクセス、外部送信、Xへの自動投稿は使いません。一般公開のWebアプリとしてデプロイする必要はありません。

## 日常の使い方

- 証券コード・会社名・優待名で検索し、一覧から選んで訂正 → 保存。
- 翌年分は既存記録を選び、年と必要な日付を変更 → 保存。前年行を残して新しい管理IDの行を追加します。
- 同じ年でも発行回や異なる優待を追加する場合は「新しい記録として複製」を使います。同じ優待・発行回・期限の重複は止めます。
- 年月の指定 →「X原稿」で確認済みデータをカテゴリ別に出力。原稿をコピーして手直しします。
- 出典などは折りたたみ欄へ。ユーザー確認なら公式URLや発行回は必須にしません。公式確認を選ぶ場合のみ期限日・公式URL・対象発行回を要求します。
- 日が分からなければ期限日は空欄。あと何日という計算には確定した期限日が必要です。

列名・列順・管理IDは編集画面が使うため変更しないでください。削除ボタンはありません。保存時に同時編集を検知し、古い内容による上書きを防ぎます。

## GitHub・サイトへの反映

この実装はシートの編集までです。サイトへの自動同期はまだ有効にしていません。GitHubとの二重編集を避けるため、シート移行後はシートを編集元にし、「CSVを保存」で出力した`expiry_master.csv`をGitHubに取り込む運用から始めます。既存の生成処理・履歴チェックはそのまま使用できます。

リアルタイム反映は、シートIDと読み取り方法を決めてから、Cloudflare APIの読み取り先をこのシートに接続します。GitHubのCSVはバックアップとして保持します。GoogleやGitHubの秘密情報を公開HTMLへ埋め込むことはありません。

## 開発時の検証

`node --test tests/sheets-editor.test.mjs`で訂正、年度追加、重複、同時編集、日付、文字列保存、X原稿を検証します。プレビューの更新は`python tools/google-sheets/build_preview.py`です。
